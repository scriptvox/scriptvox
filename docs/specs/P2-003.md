# P2-003: generated scenes in the brief

> 5 Nov 2026: `--commercial` is deleted (`docs/specs/commercial-note.md`). Text below about it is history.

- A brief scene may carry `generate: {prompt, model?, seconds?, image?}` in place of `media` or `stock`. `image` is a
  first frame inside the project, relative to the brief (image to video).
- Planned before any call (`plan_generated` in `make.rs`): the row is `model`, or else the cheapest row with a key
  that fits the aspect, `--commercial` and image to video. The length is `seconds`, or else the scene words divided
  by the measured speaking rate, rounded up to an allowed duration of the row.
- Each generated scene is one `generate` stage in the plan with its cost; the plan id covers the row, the request
  (image by hash) and the price, so a changed prompt is a new plan.
- A plan with generated scenes always gets a run id from its plan id, so a rerun of the same `make --brief` finds the
  provider jobs in its run folder and never pays twice. `make` waits up to 900 s per clip; past that, exit 9 and a
  rerun resumes.
- Refusals before any call: no key (exit 10, `generate.<key>.api_key`), `--local-only` (exit 10), replay from the
  cache (exit 2), unknown or unfit row (exit 2).
- Tests (`tests/generate.rs`): the plan picks the cheapest row and prices it ($0.13 for MiniMax 5 s); a new prompt is
  a new plan id; no submit before approval; missing key and offline ask for input; a full render with the stub voice
  and a fake fal queue makes one submit, and the rerun makes none.

# RVX-004: FFmpeg engine and `demo`

- `engine_ffmpeg::Ffmpeg`: finds FFmpeg (`SCRIPTVOX_FFMPEG`, then `PATH`) and ffprobe next to it, runs FFmpeg in the run folder, returns the last 5 stderr lines on failure, and reads back fps, frame count and size with ffprobe.
- `scriptvox demo`: 8 s, 1080x1920, 30 fps. Animated gradient (lavfi `gradients`, fixed seed), kinetic text in ASS (pop-in and fade, English and Arabic), and a soft A-major sine chord. Fonts are embedded in the binary, so the binary needs no files next to it. Render time on this WSL: about 1.5 s.
- Readback gate: frames and fps must equal the plan, or exit 3 (GATE_FAILED).
- Bit-exact output (`+bitexact`, no metadata), so two runs give identical files.
- Tests: readback, an empty `PATH` (no Python, no Node), and the golden `kinetic` (180x320, 12 fps, 4 s): two runs are identical, and PSNR against `fixtures/golden/kinetic/ref.mp4` is 38 dB or more. `just golden-bless kinetic` re-renders the reference and writes a `BLESS.md` line.

Deferred: `stages.rs` and `templates/kinetic-text/` come with the first planned run (RVX-005 and RVX-015). Until then the kinetic template lives in `demo.rs`. `--use-system` is accepted, and it is the only mode until RVX-018.

Loudness (13 Nov 2026). Fault: `check` on the demo warned, -27.9 LUFS against the target -14, and the fix line gave no command. Cause: the demo is one FFmpeg pass with a fixed gain and no master (two runs must give the same bytes). Fix: the gain of the chord is one measured number (`demo::GAIN`), since the sound is always the same. Measured: 8 s demo -14.0 LUFS, peak -5.0 dBFS; golden size -14.3 LUFS. The `loudness` finding of `check` now names the command for a file of another tool: `scriptvox edit <file> --from 0 --out <new>.mp4` (measured: -35.8 to -14.0 LUFS). Test `the_demo_is_as_loud_as_every_other_video`.

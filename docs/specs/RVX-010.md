# RVX-010: Edge TTS, voice policy and the first `make`

- Worker tool `tts.edge` (`python/scriptvox_worker/tts_edge.py`): edge-tts 7.3.1 with `boundary="WordBoundary"`, writes `voice.mp3` and `words.json`, `timing:"exact"`. HTTP 403 gives RPC `-32010` (refused, no retry); other failures give `-32011` (retryable).
- Cassettes (`python/cassettes/edge_{en,ar}.json`): word timings recorded live. The audio bytes are placeholders, so no Microsoft audio is stored in the repo.
- `registry/voices.toml`: data rows with engine, lang, network, cost, timing and terms. `scriptvox voices [--lang ar]` lists them.
- Policy (`src/voices.rs`): `--local-only` never picks a network engine. It gives exit 10, and the human action names Edge as the network option. When Edge refuses an Arabic voice, the alternatives are only engines that speak Arabic (ElevenLabs), never an English-only engine. Until 13 Nov 2026 every `explain` line carried the row's terms; the terms are now data only (`commercial-note.md`).
- **`scriptvox make --script f`** (this fills the backlog gap: no ticket created `make`): language detection (Arabic above 30% of letters), voice choice, Edge through the worker, script alignment, measured captions (84 px, BorderStyle 4: one 65% black box per caption, readable on any footage), gradient background, render, readback gate. Exit codes: 10 needs input, 5 retryable provider error, 3 readback gate.
- Tests: Python cassette tests (EN, AR, 403), Rust policy tests, and `tests/make.rs` end to end with a stub worker (success, Arabic refusal, retryable failure, `--local-only`).
- Live check on this WSL: Arabic 13.5 s video in 2.3 s of render time. English 10.7 s in 2.0 s.

Deferred: the `make` run store and events file (RVX-015), `--detach` (RVX-016), templates and own media (RVX-005, RVX-013).

## Update (3 Nov 2026): retry Edge hiccups in the worker

Found in the daily run: `make` failed with exit 5 (`NoAudioReceived`) on a 4-scene brief, and passed on the next
try. Measured with the default voice `en-US-AndrewNeural`: 2 of 24 calls failed at random, and the same texts then
worked. The worker now retries a failed or empty Edge call twice (after 1 s, then 3 s) and only then returns the
retryable error, with "after 3 tries" in the message. A 403 (voice or region refused) is never retried. Test:
`test_a_hiccup_is_retried_and_a_lasting_one_fails` (two failures then success; three failures give the error).

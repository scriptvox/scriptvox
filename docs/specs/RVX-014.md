# RVX-014: content-addressed cache

- `src/store.rs`: `cache/blobs/<b3[0:2]>/<b3>` plus `cache/keys/<key>.json` (named blobs, tool, version, `output_terms`). No index database: the path is the index.
- Key: blake3 over tool, version and canonical JSON inputs (serde_json maps are sorted, so a proptest shows reordered keys give the same key).
- Verify on read: a blob whose blake3 changed moves to `cache/quarantine/`, its key file is removed, and the read is a miss. This fixes the bug class in MPT #1740, where a corrupt entry was reused. Every write goes to `.part`, then a rename.
- `make` TTS goes through the cache. The key is tool, binary version, text, voice and rate. The worker starts on the first miss only, so a fully cached script makes zero worker or network calls. Edge entries carry `redistribution:false`.
- Tests: round trip, a flipped byte is quarantined, no `.part` left, the key-order proptest, and `tests/make.rs`: a cached rerun succeeds while the stub would fail, and a new script still calls the worker. The `make` tests now use their own `SCRIPTVOX_DATA`, so they never share the user's cache.

Deferred: `setup --bundle` (which leaves out `redistribution:false` blobs) and LRU pruning come with RVX-018 and RVX-019.

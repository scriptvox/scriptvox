# RVX-015: run store, state.db placement and events

- `src/run.rs`: `Run::create` makes `.scriptvox/runs/<id>/`, writes `.scriptvox/.gitignore` (`*`), inserts a `running` row, and logs `run.start`. `Run::finish` writes `result.json`, logs `run.end` and updates the row (status, exit, video, finished time).
- `make` runs its whole body after run creation inside one closure, so every outcome (ok, needs input, gate failed, provider error) is recorded. Envelopes carry `run_id` and `events_file`. Milestones are `progress` events.
- `state.db` placement: the filesystem type comes from `/proc/self/mountinfo` (no new dependency). 9p, drvfs, v9fs, cifs, smb, nfs, fuse and OneDrive paths use `<data>/state/<FNV path hash>.db` with `journal_mode=DELETE`. Local disks use `.scriptvox/state.db` with WAL. A 10 s busy timeout applies everywhere.
- `scriptvox status` lists the last 20 runs from `state.db`.
- `schemas/event.json` (`scriptvox.event/v1`): `v`, `t` (RFC 3339 UTC), `run`, `type`. Timestamps come from our own UTC formatter (no chrono).
- Tests: WAL and `.gitignore` on a local folder; the real CLI on `/mnt/c` (WSL) puts the db in the data folder with `journal_mode=delete`; every events line of a stub `make` run follows the schema, and the last line is `run.end`.

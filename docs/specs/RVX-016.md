# RVX-016: detach, wait, status and cancel

- `make --detach`: the parent creates the run, starts the supervisor (this binary again with a hidden `--run-id`) in a new process group (`process_group(0)`, std only), sends its stdio to `supervisor.log`, records the pid in `state.db`, and returns in about 4 ms: exit 0, `status:"running"`, `next:["scriptvox wait <id>"]`.
- `wait <id> [--timeout 100]`: polls `result.json` and replays it, with its exit code. A replay keeps the run's status `cancelled` or `approval_needed`. A timeout gives exit 9 with `next`, `error.retryable: true`, and an `error.fix` that says the run is alive, names its stage (its last `progress` event) and gives the exact command `scriptvox wait <id> --timeout <n>`. The default stays 100 s: the shortest agent shell limit seen is 120 s, and a `wait` that the shell stops gives no envelope at all. A supervisor that died without a result (its pid is gone) gives exit 1 `SVX_SUPERVISOR_DIED`, and its fix is `scriptvox resume <id>` (and the log, for a detached run). `status` shows that same run as `died`. `status <id>` also gives `alive` (true or false), and for a run with no result `stage`, `idle_s` (the age of `events.jsonl`) and a `next` of `wait` (alive) or `resume` (dead).
- A foreground `make` (no `--detach`) stops when its caller's shell stops it. Its first stderr line and progress event give the run id and `scriptvox resume <id>`. The default did not change to detach: agent mode includes `CI`, where tests and scripts read the video from the answer of `make`. `cancel` stops a supervisor by its name, its run id or this binary. A live process that is none of these is left alone, and `cancel` gives exit 1 with no result written.
- `cancel <id>`: TERM to the supervisor's whole group (worker and FFmpeg too; `taskkill /T` on Windows), then `result.json` with exit 8, a `run.end` event, and the db row set to `cancelled`. A process that is still alive after TERM and KILL gives exit 1 with no result written. Windows checks a pid and its image name with `tasklist`.
- `status [<id>]`: all runs, or one run with its last 10 events.
- The final video goes to `scriptvox-out/<run>.mp4`, with the SRT next to it, unless `--out` is given.
- Windows: flip rule (d). `--detach` runs in the foreground with a `warning` field.
- Tests (`tests/detach.rs`, shared stub env in `tests/common/`): detach then wait; SIGKILL of the caller's whole process group, and the run still finishes; wait timeout exit 9; cancel exit 8, and the result stays cancelled; stderr has 15 lines or fewer in agent mode.

Deferred: EPIPE handling (human mode cancels, agent mode detaches) needs a signal handler. Today a closed stdout ends the foreground process, and a detached run is not affected.

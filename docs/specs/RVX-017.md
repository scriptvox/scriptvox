# RVX-017: chunked render, watchdog and resume

Ideas: RM #11864 (no resume), HF #1231 and #6029 (render hangs). Design and code are ScriptVox's own.

- `src/ranges.rs`: chunks of `SCRIPTVOX_CHUNK_S` seconds (default 10). Half-open frame ranges cover the timeline with no overlap, and a resume cuts at the same boundaries (proptests).
- `src/render.rs`: one FFmpeg pass writes video-only chunks with the `segment` muxer and `-force_key_frames` at each chunk start. Each attempt has its own `list_<start>.csv`. A chunk is done when a list names it and its file exists. The chunk folder is `.scriptvox/chunks/<render key>/`. The key is blake3 over the version, inputs (paths and file bytes), graph, captions, encoder, fps and length, and it leaves out run folders and audio. So a rerun of the same command (TTS from the cache) resumes at the first missing chunk with `trim=start_frame`. The stitch is a concat stream copy, and the audio is encoded once in the final mux. The chunks are removed after a good final file.
- Watchdog (`Ffmpeg::run_watched`): `-progress pipe:1` lines are the heartbeat. No line for `SCRIPTVOX_WATCHDOG_S` (default 120) kills FFmpeg, and the run gives exit 7 with the fix "Run the same command again: finished chunks are kept and the render resumes."
- Found during tests: with one chunk left, the segment muxer splits every 2 s at natural keyframes (scene cuts), so frames went missing. The readback gate caught it (67 of 108 frames). Fix: a huge `segment_time` for a single chunk.
- Metrics: `chunks`, `resumed_from_chunk`.
- Tests (`tests/resume.rs`): own media, 4 chunks of 1 s, a fault after 2 chunks (exit 1), the rerun resumes at chunk 2, and the result matches a clean render (PSNR ≥ 50 dB or identical). A fake ffmpeg that hangs in the render pass gives exit 7 in about 2 s.

Readback after a resume (13 Nov 2026). The error `readback: N frames, planned M` had no fix line. The chunk folder is removed when the chunks are joined, before the readback, so after this error no kept chunk is left. The fix line says so: when the render resumed from kept chunks, "run the same command again, and every frame is rendered new"; when it did not, run again and send `scriptvox report` if the count is wrong again. Test `a_bad_kept_chunk_fails_the_readback_with_a_fix_that_works`: a kept chunk cut to 3 frames gives exit 3 with the fix, and the same command then gives exit 0 with `resumed_from_chunk` 0.

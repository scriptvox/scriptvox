# RVX-019: doctor and uninstall

- `scriptvox doctor [--fix] [--redact] [--offline]` (`src/doctor.rs`): system (OS, CPUs), memory (MemAvailable), disk (`df -Pk`), WSL with the project filesystem type (it warns on 9p or drvfs: state.db moves and the project is slow), `/dev/shm` in containers, FFmpeg (path, licence class, encoder from a real 1-frame probe), the embedded fonts (they parse and measure Latin and Arabic), uv, keys by name and source only, and a test fetch to github.com and the Edge TTS host (`tls_intercept` against `blocked`).
- Every check has `status`, `detail`, `fix` (unless ok) and `fix_safe`. Exit: 0 with no failure, 1 when a failure has a safe fix (`scriptvox doctor --fix` downloads the pinned tools), 10 with `kind:"dependency"` when a failure needs the user. The table is locked by an insta snapshot.
- `mode_ready`: `local` (FFmpeg ok: renders work offline; v0.1 has no local voice), `hybrid` (plus uv for Edge), `cloud` (plus the ElevenLabs key).
- `--redact`: the home folder becomes `~` and the user name becomes `<user>`. Key values never appear (the global redactor).
- `scriptvox uninstall [--purge]`: shows, or with `--purge` deletes, the data folder (tools, worker, cache, state of drvfs projects). Projects are not touched.
- Live on this WSL: all checks ok, `mode_ready: local, hybrid`.
- Tests: a clean HOME with FFmpeg is ok and lists modes; missing FFmpeg is exit 1 with a safe fix; `--redact` hides a home path that the plain output shows; uninstall needs `--purge`.

# RVX-020: keys

- `src/keys.rs`: order is environment variable (`ELEVENLABS_API_KEY`, `PEXELS_API_KEY`, `PIXABAY_API_KEY`), then `keys.toml` in `SCRIPTVOX_CONFIG`, `%APPDATA%\scriptvox`, `$XDG_CONFIG_HOME/scriptvox` or `~/.config/scriptvox`.
- `scriptvox keys set <provider> [--stdin]`: the value comes from stdin (pipe) or a no-echo terminal prompt, never from argv. The file is written through a temp file with mode 0600 (Unix) or a user-only ACL through `icacls` (Windows). An agent with no `--stdin` gets exit 10 `kind:"secret"` with the command for the human, so it never asks for the value in chat.
- `scriptvox keys list`: provider, variable name and source (`env`, `keys.toml`, `none`). Never the value. `doctor` uses the same sources, and `mode_ready.cloud` uses `keys::resolve`.
- The global redactor now includes `keys.toml` values, so a key from the file is `***` in every output.
- Voice availability (`voices::Voice::available`) uses `keys::resolve`.
- Tests: `--stdin` writes mode 0600 and prints no value; env wins over keys.toml; doctor shows `source: keys.toml` and no value; an agent without stdin gets `secret`; a keys.toml value is redacted in output.

Audit fix, 9 Nov 2026: `keys set` stops and writes nothing when keys.toml exists and does not parse. `keys list` and `doctor` report it as `keys_file`. Every message gives the line number only: TOML's own message quotes the line, and that line can hold a key.

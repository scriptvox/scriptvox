# RVX-021: stock video rows

- `registry/providers.toml`: Pexels and Pixabay as data rows (search URL template, header or query auth, small JSON paths for results, files, size, credit and page, site, output terms). `SCRIPTVOX_PROVIDERS` overrides the file.
- `src/http_rows.rs`: a path reader (`a.b`, `a[*]`, `a.*`), search (MP4 file closest above the frame's short side, else the largest), Range resume (`.part` named by a URL hash; a server that ignores Range restarts), and `auto_terms` (the 2 longest words per caption page, a weak fallback).
- `make --stock "t1,t2,..."` (one term per shot, cycled; the calling agent writes the terms, per D3) or `--stock auto`. Shots follow the caption pages. An unused clip at least as long as the shot comes first. A 429 or 5xx moves to the next provider and writes a `fallback` event. Clips go through the cache with the provider's terms. `credits.txt` goes in the run folder and next to the video (`scriptvox-out/<run>.credits.txt`), and `artifacts.credits` points to it.
- No key: exit 10 `kind:"secret"`. The alternatives are the free narrated gradient template (no `--stock`) and `--media`. Under `--local-only`, `--stock` is refused (network).
- Tests (`tests/stock.rs`, local fake provider server): clips in script order with one credit line per shot; a Pexels 429 falls back to Pixabay with an event; no key gives secret with the free template; a `.part` resumes with `Range: bytes=1000-` and the file is byte-identical.
- Not tested live: no Pexels or Pixabay key on this machine.

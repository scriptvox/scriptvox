# RVX-027: resume --brief and the §4 session

- Every run saves its request (`request.json`: the script text and all settings, without the approval token).
- `scriptvox resume <run> [--brief f] [--duration S] [--wait]`: loads the parent's request, puts the brief's fields and new flags on top, and makes a child run `<run>.1` (then `.2`, ...) with `parent_run` recorded. It runs detached by default, through the hidden `_run <id>` supervisor command, and returns exit 0 with `status:"running"` and `next:["scriptvox wait <child>"]`. This follows the exit table (9 is only for `wait` timeouts), not the exit 9 in the plan's session sketch. `--wait` runs in the foreground. The child's video is next to the parent's (`name.1.mp4` for a parent `--out name.mp4`), and the detached answer gives the path in `out`; a parent whose `--out` file is not on disk (it failed, was stopped or was killed before the render) leaves the name to the child.
- `scriptvox plan ...` is an alias for `scriptvox make ... --plan`.
- Two bugs found and fixed by the session test:
  1. `wait` rebuilt the exit code from the error-code name, so `SVX_NEEDS_SHORTER_SCRIPT` (exit 3) came back as 1. `result.json` now stores the numeric `exit`, and `wait` replays it.
  2. `wait` dropped command-specific fields (`parent_run`, `lang`, `idempotent`, `findings`, `next`). The replay now copies every field.
- `tests/session_s4.rs` runs the §4 sequence with the stub worker and an Arabic brief with own media: doctor exit 0, plan cost 0, make --detach exit 0, wait exit 3 `SVX_NEEDS_SHORTER_SCRIPT` (measured after TTS, before render), resume gives child `.1`, wait on the child gives exit 0 with `parent_run`, and snapshot `--sheet 9` writes a PNG.

Deviation: the §4 sketch expected a cache hit on media for the child. Own media is used in place (not copied into the cache), so there is nothing to hit. TTS cache hits are tested in RVX-014.

# RVX-028: ElevenLabs paid TTS through ledger.reserve

Open question Q6 (paid TTS vendor) uses the recommended default: ElevenLabs.

- Worker tool `tts.elevenlabs` (`python/scriptvox_worker/tts_elevenlabs.py`, stdlib `urllib`, no new dependency): it asks the core `ledger.reserve` with its estimate first. A refused reserve raises before any HTTP call. Then it POSTs to `/v1/text-to-speech/{voice}/with-timestamps` (`SCRIPTVOX_ELEVENLABS_URL` overrides the base for tests), writes the MP3, and builds word times from the character alignment (`timing:"exact"`). 401 and 403 give refused, and 429, 5xx and network errors give retryable. The key comes from `ELEVENLABS_API_KEY` in the worker environment only.
- RPC: `Worker::request_with` answers worker-to-core requests. The Python `Ctx.request` waits for the answer, because the serve loop reads stdin line by line.
- `plan::Ledger` (Rust): `ledger.reserve` reserves under `BEGIN IMMEDIATE` against the cap (`--max-spend`, default the approved plan cost). It releases on failure and commits the tool's reported cost on success. A refused reserve gives exit 4 `SVX_SPEND_CAP`. This replaces RVX-026's core-side pre-reservation, so nothing is counted twice.
- Keys: the worker command removes every provider key from its environment and adds only the one for the engine in use (from env or keys.toml).
- `registry/voices.toml`: the ElevenLabs row uses the premade voice `21m00Tcm4TlvDq8ikWAM` and the model `eleven_multilingual_v2`.
- Tests: Python (alignment to words; reserve before HTTP; refused reserve makes no request; 400/401/404/422 as refused and 429/503 as retryable (400, 404 and 422 charge nothing, audit rows-8); the key is not in the body), the contract fixture `ledger_reserve.jsonl` replayed by both sides, and `tests/elevenlabs.rs` with the real worker and a fake API: no call before approval, one call after it, a committed ledger row with a cost, no key in any output, and a refused reserve makes zero HTTP requests.
- Not tested live: no ElevenLabs key on this machine.

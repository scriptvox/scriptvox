# RVX-029: opt-in local voice (Kokoro) and setup voice-local

- `plugins/kokoro/` (GPL-3.0-or-later): kokoro-onnx 0.6.1, whose G2P (phonemizer, espeak-ng) is GPL-3.0. It runs as its own process with its own venv. It imports the Apache RPC module (`scriptvox_worker.rpc`); nothing Apache imports it. One tool, `tts.kokoro`: WAV output, and word times `estimated` (the audio length spread by characters), because Kokoro gives no word events.
- `toolchain.lock`: the model `kokoro-v1.0.int8.onnx` (92.4 MB) and `voices-v1.0.bin` (28.2 MB) as raw-file pins with target `any`. GitHub publishes no digest for these assets, so they are pinned by the sha256 of the first download (`6e742170…` and `bca610b8…`). Every later install is checked against the pin.
- `scriptvox setup voice-local [--dry-run] [--accept-gpl]`: shows the GPL notice and about 120 MB of model files. Without `--accept-gpl` it gives exit 10 `kind:"dependency"` with the notice. With it: downloads the pins, unpacks the embedded plugin, and prepares its venv.
- `registry/voices.toml`: `kokoro` rows `af_heart` and `am_michael` (English, local, free, commercial use allowed, `timing: estimated`). They are available only after `setup voice-local`.
- `make`: a Kokoro voice starts the plugin process (`provision::kokoro_command`, with the worker and plugin folders on `PYTHONPATH` and the model paths in the environment). `--local-only` English now picks Kokoro when installed. When it is not installed, the NEEDS_INPUT points to `scriptvox setup voice-local --accept-gpl`. `explain` and the receipt report the real timing (`estimated`).
- Live on this WSL: `setup voice-local --accept-gpl` took 43 s. A `--local-only` English own-media video passed every gate.
- Found and fixed on the way (all engines): the video length was not a whole number of frames, so the audio was cut 1 to 2 frames past the video (drift 42 ms, the gate failed). The length is now rounded to whole frames, and the final mux uses `-shortest` with padded audio. Drift is now 4.3 ms.
- Tests: the notice gate (exit 10, then `--dry-run` exit 0) and the `--local-only` guidance, with no download.
- uv folders: ScriptVox puts the uv cache and Python in its data folder only when the user has not set `UV_CACHE_DIR` or `UV_PYTHON_INSTALL_DIR`. The test environment shares the user's uv cache (one test suite went from 98 s to 10 s).
- Update: `-shortest` was replaced. Under heavy parallel load it cut 2 video frames (readback 106 of 108, found by the full CI). The audio is now trimmed in the filter graph to the frame-exact sample count (`atrim=end_sample`). Drift is 0.7 ms.

## Path limit (G003, 5 Nov 2026)

espeak-ng keeps its data path in a 160-byte buffer. Measured with a real `setup voice-local` and `make --tts kokoro` on Linux, with a new script each time so no cached voice hid it: a data path of 150, 155, 158 and 159 bytes speaks; 160, 161, 162, 164, 165, 180, 200, 230 and 255 stop with `worker_crashed`. The part of the path under the data folder is 103 characters, so the data folder may have at most 56, which on Linux is a home path of at most 35. `setup voice-local`, also with `--dry-run`, now refuses a longer folder before any download, and says to set `SCRIPTVOX_DATA`. Not run on Windows: the buffer is in the same C library, and the venv layout there is `Lib\\site-packages`, 11 bytes shorter, so the check computes the limit per OS and the fix text gives the right number.

- Update, 7 Nov 2026 (audit M3): GPL-3.0 needs no acceptance to run a program. `setup voice-local` shows the notice once (stderr and the `notice` field) and installs; `--accept-gpl` is accepted, hidden and ignored for one version. The dry run still lists the notice and the downloads.

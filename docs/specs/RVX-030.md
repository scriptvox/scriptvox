# RVX-030: receipt, embedded recipe, explain, replay and remake

Idea: ComfyUI `nodes_video.py` (the workflow saved in the video's metadata). Ours is ScriptVox's own code.

- Every MP4 carries its recipe in the `comment` tag: `{"scriptvox": version, "plan_id", "request"}`. The request is the saved run request (script, voice, length, aspect, media, music, stock terms) plus the exact stock clips used. It never holds a key: keys are never part of a request. `--no-embed` (global) leaves the tag out.
- `receipt.json` in the run folder: run and plan ids, video, length, cost, voice with terms and timing, encoder, tool pins, credits file, stock picks, and whether the recipe was embedded. `artifacts.receipt` points to it.
- `scriptvox explain <file.mp4>`: prints the recipe. A file without one gives exit 1 with a fix.
- `scriptvox replay <file.mp4> [--out f]`: rebuilds from the recipe with the cache only. A voice or stock miss gives exit 1 `SVX_CACHE_MISS`, never a provider call. Stock uses the recorded picks, so no search runs.
- `scriptvox remake <file.mp4> [--out f]`: the same, with provider calls allowed. The normal plan rules apply, so a paid recipe gives exit 4 until approved, and a free one runs. This is `make --from` in the plan, a verb of its own here.
- Tests: the recipe holds the script and not the key set in the environment; `explain` returns the music; a warm replay succeeds while the stub would fail any voice call; a cold-cache replay gives `SVX_CACHE_MISS`; `remake` of a free recipe on a cold cache runs; `--no-embed` leaves no tag; a stock replay makes zero HTTP requests to the fake provider.

`explain`, `replay` and `remake` on a path that is not a file give a usage error that names the path (audit contract-8).

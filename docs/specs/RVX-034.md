# RVX-034: local packaging

- Static Linux binary: `just build-musl` (release profile: thin LTO, stripped) with the musl cross gcc from musl.cc in `~/.local/opt/x86_64-linux-musl-cross/`. The Arch `musl` package could not be installed: the mirror no longer has the file the local database lists, and `pacman -Sy` (a partial upgrade) is not safe on a shared machine. musl.cc publishes no checksum, so the toolchain is trust-on-first-use (gcc sha256 starts 2230cb8079eec851). Result: a 10.9 MB static-pie binary, built in 75 s on 2 cores.
- `just package`: `dist/scriptvox-<v>-x86_64-unknown-linux-musl.tar.gz` (binary, LICENSE, README, CREDITS, `THIRD_PARTY.md`, OFL, install.sh) plus a `.sha256` file. `/dist` is git-ignored.
- `install.sh` (Linux): a local tarball (`--from`) or a release URL, sha256 check, `~/.local/bin` (or `SCRIPTVOX_BIN_DIR`), prints the absolute path, never sudo, never edits profiles. `install.ps1` (Windows): the same into `%LOCALAPPDATA%\scriptvox\bin`, no admin, PATH untouched.
- `docker/render.Dockerfile`, `docker/SOURCES.md`, `docker/fetch-sources.sh` (GPL sources for the FFmpeg build): written, not built. Images build on a build machine, not the workstation (owner rule), and nothing is published.
- `dist-workspace.toml` (cargo-dist 0.33.1): written, not built.
- Found by the clean-environment check (`scripts/clean-check.sh`) and fixed:
  1. `scriptvox ... | head -1` panicked on a broken pipe. Output now ignores a closed stdout or stderr.
  2. The first voice run did `uv sync` inside the 300 s RPC hello timeout and failed on a slow network. `provision::prepare_worker` now syncs as its own step (3 tries, progress, ready stamp). A failure is a retryable exit 5. `setup` pre-warms it.
  3. uv's cache and Python went to `~/.cache`. They now live in the data folder (`uv-cache/`, `python/`), so `uninstall --purge` removes them.
  4. Pinned downloads retry twice on network errors.
- `--version` now reports the FFmpeg pin.
- The WSL checklist passed (see `docs/release/wsl-checklist.md`).

Not done: the Windows build (open question Q2: cargo-xwin in WSL or a native toolchain), the Windows 11 checklist, and the container test (it must run on a build machine).
